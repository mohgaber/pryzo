# Deploy Pryzo Backend to Render (Free Tier)

Deploy the FastAPI backend so the Flutter app on a real phone can reach
it. Everything here is free; no credit card is needed for any step.
No secrets are in this repo — `REFRESH_TOKEN` is generated by Render
and `DATABASE_URL` is wired by the Blueprint.

**Accounts needed (all free):** GitHub, Render (render.com),
cron-job.org. Nothing is created for you here — the steps below are
done by a human in those dashboards.

## 0. What is already done

- `render.yaml` (repo root) — Blueprint: free web service `pryzo-api`
  (Python, `pip install -r requirements.txt`,
  `uvicorn main:app --host 0.0.0.0 --port $PORT`, health check
  `/health`) + free PostgreSQL `pryzo-db` wired as `DATABASE_URL`.
- `POST /admin/refresh` — token-guarded refresh trigger (see step 5
  for why it returns immediately instead of running inline).
- `backend/runtime.txt` — pins Python 3.12.0.
- The repo is committed locally (`git init` done in `~/workspace/pryzo`).
  **No remote is configured and nothing is pushed** — step 1 does that.

## 1. Push the code to GitHub

1. On github.com, create a **new empty repository** named `pryzo`
   (no README, no .gitignore, no license — the code is already here).
2. From this machine:

```bash
cd ~/workspace/pryzo
git remote add origin https://github.com/<your-username>/pryzo.git
git push -u origin main
```

## 2. Deploy the Blueprint on Render

1. Create an account at render.com (email + password, no card).
2. **New > Blueprint**, connect your GitHub account, pick the `pryzo` repo.
3. Render shows the plan: web service `pryzo-api` (Free) + database
   `pryzo-db` (Free). Click **Apply**. First deploy takes a few
   minutes; the service health check (`GET /health`) must pass.
4. Copy the service URL from the dashboard — it looks like
   `https://pryzo-api.onrender.com` (if that name is taken, Render
   assigns a slightly different one; **always copy the exact URL from
   the dashboard** and use it in steps 5–7).

## 3. Environment variables (already mostly done by the Blueprint)

- `DATABASE_URL` — set automatically from the `pryzo-db` database.
  Do not set it by hand.
- `REFRESH_TOKEN` — **generated by Render** on first deploy. Copy it
  from the dashboard: service > **Environment** > `REFRESH_TOKEN`
  (click to reveal). You need it for step 5. If you ever rotate it
  (change the value in Render), update the cron-job.org job too.

## 4. Seed the production database (once)

The fresh Postgres is empty. Seed it from the Render Shell
(service > **Shell** tab). First check where the shell starts:

```bash
ls
```

- If `ls` shows `main.py` (you are in `backend/`): run `python seed.py`
- If `ls` shows `backend/` and `app/` (you are in the repo root):
  run `cd backend && python seed.py`

`seed.py` is idempotent (safe to re-run) and inserts the 7 stores,
9 products and 24 **SAMPLE** prices (labelled `is_sample=True`).
Live prices arrive via the refresh job (step 5) — the first scheduled
refresh will add them.

## 5. Schedule the refresh — cron-job.org (free, no card)

Render free has no cron jobs, so an external scheduler calls the API.

Create a free account at cron-job.org and add **two** jobs
(replace `pryzo-api.onrender.com` with your exact service URL):

| Job | URL | Method | Schedule | Notes |
|---|---|---|---|---|
| `pryzo-keep-awake` | `https://pryzo-api.onrender.com/health` | GET | every 10 minutes | Keeps the free service awake (it sleeps after 15 min idle) |
| `pryzo-refresh` | `https://pryzo-api.onrender.com/admin/refresh` | POST | every 30 minutes | Header: `X-Refresh-Token: <paste REFRESH_TOKEN from step 3>` |

Why two jobs: the keep-awake ping every 10 minutes means the service
is warm when the refresh call arrives; without it, the refresh call
would hit a sleeping service and spend most of its time waking it up.

**Why the refresh endpoint returns immediately:** a full refresh pass
fetches 9 store pages and takes ~30–90 seconds, but cron-job.org
times out after 30 seconds and would kill a synchronous call. So
`POST /admin/refresh` starts the refresh in a background thread and
returns `202 {"status": "started"}` at once. Check the run's counts
afterwards:

```bash
curl -s https://pryzo-api.onrender.com/admin/refresh/status \
  -H "X-Refresh-Token: <your REFRESH_TOKEN>"
# {"running": false, "last_run": {"started_at": ..., "finished_at": ...,
#  "status": "ok", "summary": {"checked": 9, "updated": 9, "failed": 0, "skipped": 10}}}
```

cron-job.org free-tier facts: unlimited jobs, runs as often as once a
minute, no card. Limits: 30-second execution timeout (hence the
background design above), only the last 50 executions are viewable,
and a job is **auto-disabled after 25 consecutive failures** — if
prices stop updating, check the job's execution history first.

## 6. Verify the live API

```bash
BASE=https://pryzo-api.onrender.com   # your exact service URL
curl -s $BASE/health
# {"status": "ok"}
curl -s "$BASE/search?q=playstation"
# products, lowest_price is LIVE-only (null until the first refresh)
curl -s $BASE/products/1/compare
# per-store LIVE prices, cheapest first; empty prices list until the first refresh
```

After the first scheduled refresh (within 30 minutes of step 5, or
trigger it once by hand with the same POST as the cron job), the
compare call should show live prices — e.g. PS5 cheapest Jumia
50,000 EGP.

## 7. Point the Flutter app at the live URL and rebuild the APK

1. In `app/lib/services/api_service.dart`, change the **one** constant:

```dart
static const String defaultBaseUrl = 'https://pryzo-api.onrender.com';
```

2. `cd app && flutter analyze` (must stay 0 errors).
3. Rebuild the APK with `~/apkbuild/pryzo/build_pryzo.py` — **re-run
   `flutter assemble` first** and confirm a fresh `libapp.so`
   (timestamp/md5), otherwise the APK contains stale code (this
   burned us once already). Verify with `aapt2 dump badging` +
   `zipalign -c` as before.
4. Install the new APK on the phone. The amber "أسعار تجريبية"
   banner disappears once the app reaches the live backend; if the
   banner is still there, the app cannot reach the URL (check the
   URL and that the service is awake).

## Free-tier limits — read before relying on this

- **Web service sleeps after 15 min idle.** First request after sleep
  takes ~1 minute. The keep-awake job (step 5) prevents this in
  practice.
- **Free PostgreSQL expires 30 days after creation**, then Render
  deletes it after a 14-day grace period. It has **no backups**.
  Before day 30: upgrade the database to a paid plan (smallest is
  $6/month) **or** create a new free database, point `DATABASE_URL`
  at it, and re-run step 4 (seed) — price history is lost either
  way unless you export it first.
- 750 free instance hours/month, 5 GB outbound bandwidth/month.
- No persistent disk on the free service (irrelevant here — all data
  lives in Postgres, and the SQLite `pryzo.db` fallback is local-dev
  only; Render always has `DATABASE_URL` set).

## Troubleshooting

| Symptom | Likely cause / fix |
|---|---|
| Blueprint deploy fails | Read the build logs in Render. Usual suspect: `pip install` — check `backend/requirements.txt`. |
| Service shows "not found" / `/health` 404 | Wrong service URL — copy it exactly from the dashboard. |
| `POST /admin/refresh` returns **503** | `REFRESH_TOKEN` is not set on the service (Blueprint generates it; check service > Environment). |
| `POST /admin/refresh` returns **401** | Token mismatch — copy `REFRESH_TOKEN` again from the Render dashboard into the cron-job.org header. |
| `POST /admin/refresh` returns **409** | A refresh is already running — wait and check `/admin/refresh/status`. |
| `/admin/refresh/status` shows `"status": "error"` | Read the error + the Render logs (service > Logs). Common cause: a store blocking the crawler (see `backend/README.md` crawler notes). |
| Prices never update / job auto-disabled | cron-job.org disables a job after 25 consecutive failures — check its execution history, fix the URL/token, re-enable it. |
| App still shows the "أسعار تجريبية" banner | The app cannot reach the backend: wrong `defaultBaseUrl`, service asleep (wait a minute for the cold start), or no live prices yet (wait for the first refresh). |
